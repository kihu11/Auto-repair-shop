Название проекта: Автомастерская

Фуекциональные требования:
Общее описание системы
1.1 Клиент-серверно веб-приложение — симулятор автомастерской.
1.2 Вся бизнес-логика выполняется в браузере на чистом JavaScript.
1.3 Интерфейс — HTML/CSS.
1.4 Архитектура — модульная, с разделением на слои: модели, сервисы, репозитории, UI.

Хранение
2.1 localStorage: ключи mechanics, orders, garages, counters
2.2 Автосохранение после каждого изменения
2.3 При первом запуске — тестовые данные (6 механиков, 2 гаража, 2 заказа)

Сервисы
3.1 MechanicService: добавить, удалить, получить всех, получить свободных
3.2 OrderService: создать, закрыть, отменить, назначить механика, получить все
3.3 GarageService: добавить, получить все, подсчёт мест (всего/занято/свободно)

UI (одна страница)
4.1 Панель статистики: заказы, механики, места в гараже
4.2 Таблица механиков: id, имя, опыт, статус, заказ + кнопки "Добавить", "Удалить"
4.3 Таблица заказов: id, название, авто, дата, цена, статус, механик + кнопки "Создать", "Закрыть", "Отменить"
4.4 Блок гаража: список гаражей


Технологический стек:
Языки и стандарты
1.1 JavaScript
1.2 HTML5 
1.3 CSS3 

Инструменты разработки
2.1 Редактор кода: VS Code 
2.2 Локальный сервер: Live Server (расширение VS Code)
2.3 Браузерные DevTools — отладка, просмотр localStorage, инспекция DOM



3. Анализ
Приоритет 1 
1. Учёт заказов (создание / закрытие / отмена)
2. Управление механиками (добавление / удаление / статус)
3. Назначение механика на заказ
4. Учёт мест в гараже (занято / свободно)
5. Панель статистики (заказы, выручка, загрузка)
6. Сохранение состояния (localStorage)
7. Статусы заказов (ACTIVE / COMPLETED / CANCELED)

Приоритет 2 (Важные — расширяют функциональность)
8. Фильтрация заказов по статусу
9. Валидация форм с сообщениями об ошибках
10. Форматирование дат и цен (Intl)
11. Автоподстановка даты завершения = сегодня
12. Запрет удаления механика с активным заказом
13. Карточка механика с текущим заказом
14. Сброс данных / новая игра
